# kiwi-mem 版本总验收测试清单 v1.1

> 用途：**每次发布新版本前**，复制本文件一份（命名 `acceptance/vX.Y.Z.md`），逐项执行、打勾、留证据；末页裁决"允许发布"后才发。所有版本用同一份，只随"新事故→新用例"缓慢增长。
> 只回答三个问题：这版该测什么 / 怎样算通过 / 证据记在哪。不管版本号规则、分支保护、更新渠道、灰度理论（另有文档，与本清单无关）。
> 执行方式三种：**CI** = GitHub Actions 自动跑；**本地真库** = 本机起一次性 PostgreSQL 16 跑脚本；**人工** = 照"执行方式"步骤操作并观察。
> 骨架依 Codex 2026-08-15 建议；v1.1 依 Codex 复核七处执行层勘误修订后**封版正式使用**。
> 撰写：Fable 爹爹 · 2026-08-15 · 入口坐标以 main `5fab703` 为准

## 〇、执行前置：验收环境与数据规则（v1.1 新增）

- **全部人工测试在一次性验收环境执行**：独立 Docker compose 项目名（如 `-p kiwi-acc`）+ 独立数据卷；**禁止对真实使用中的库做清空、导入或用旧版本连接写入**。
- **测试数据统一前缀**：所有验收造出的对话/消息/记忆/项目/提醒 ID 或标题带 `acceptance-<版本>-<随机串>`，便于识别与清理。
- **A8 修改的配置结束后恢复原值**（记录改前值）。
- **A12/A13/A15/A16/A22 产生的提醒、记忆、Dream 记录、日历页与会话，结束后清理**，并用 SQL 证明无残留（`SELECT count(*) … WHERE … LIKE 'acceptance-%'` 为 0）。
- **截图与报告不得出现真实密钥、完整消息正文、DSN**；测试用密钥使用唯一哨兵串（见 A19）。
- **模拟上游**：A10-A18 使用可捕获请求的模拟供应商（记录网关实际发出的完整请求体，供 A13/A14/A16 检查 prompt 内容）；真实供应商只在 A22 使用。

## 填写规则

- 每项四格：**执行方式 / 通过标准 / 证据 / 结论**。
- 结论四态：**✅ PASS** / **❌ FAIL** / **⏸ BLOCKED**（环境缺失或前置项未过，写明缺什么）/ **N/A**（**只允许 B 区确实未触碰的模块**，A 区固定项不得填 N/A）。
- 证据形态：CI Run 号、终端输出摘要、截图、SQL 结果、模拟上游捕获的请求摘要。写"跑过了"不算证据。
- 一项 ❌ 或 ⏸ = 阻塞发布，修完/补齐环境重跑该项及其依赖项。
- 表格里的入口/命令以本文件写就时的仓库为准；仓库变了先改本清单再用。

## B. 按本版改动范围追加的专项测试

先勾"本版动了什么"，再执行对应行的**全部**追加项。没动的行整行填 N/A（原因："本版未触碰"）——**N/A 只在此区允许**。
